# Gather Roadmap

这份路线图描述的是**范围与验收门槛**，不是发布日期承诺。所有时间从 Phase 0 启动起算，按“一人全职、每周可稳定投入”估算；兼职、团队、外部依赖都会改变结果。

当前快照（2026-11-22）处于 Phase 1：Phase 0 的干净环境 CI、项目站、桌面基础打开/保存已闭环；Phase 1 已完成 CRLF/BOM 保真、保存时冲突拒绝、打开文件重置撤销栈、生产 CSP、自动恢复快照、实时外部变更提示、原子写入故障注入、POSIX 只读目录测试、文件夹工作区与侧栏切换、GFM 表格/本地图片实时预览与安全外链、桌面 PDF/HTML 导出、Windows staging 目录包，以及仓库内调试/验证记录。IME/Linux 桌面矩阵、冲突合并、Windows 只读/真实满盘/断电矩阵、远程图片自动加载、DOCX、签名安装包仍未完成。剩余收尾项见 [README 的明确未完成项](../README.md#明确未完成项)。

## 总览

| 阶段 | 主题 | 量级 | 累计时间（一人全职） | 出口标志 |
| --- | --- | --- | --- | --- |
| Phase 0 | 可运行骨架 | 2 周 | 第 2 周 | 干净环境四命令全绿；打开/保存不丢稿；站点可访问 |
| Phase 1 | 编辑可靠性与文件安全 | 4–6 周 | 第 6–8 周 | 8 小时 dogfood；IME 矩阵签字；5 MiB 文档可用 |
| Phase 2 | AI 审阅与 Tauri bake-off | 6–10 周 | 第 12–18 周（约第 3–4.5 个月） | 默认不上传；逐块 diff；四项硬门槛有结论 |
| Beta 准备 | 签名、隐私、文档、发布流程 | 2–4 个月 | 第 5–8 个月 | 安装/升级/回滚可演练；支持与安全通道可用 |
| 公开 beta | 真实用户与反馈 | 从第 6–9 个月开始 | 第 6–9 个月起 | 签名安装包；数据安全门槛通过；beta 名单可用 |
| Phase 3 | beta 加固与生态 | 3–5 个月 | 第 9–14 个月 | DOCX；插件 SDK；自动更新与回滚 |
| Phase 4 | 1.0 | 3–6 个月 | 第 12–18 个月 | 30 天无 P0 数据事故；文档/迁移/支持完备 |

“公开 beta 6–9 个月”是量级估算，不是承诺日期。两到四人的团队可能压缩到 3–6 个月，但 IME、Linux 矩阵、签名、数据安全测试不能按人数线性压缩。

## 阶段原则

1. **数据安全优先于功能。** 没有通过丢稿、冲突、恢复测试的版本不进入 beta。
2. **Markdown 文件是唯一真相。** 任何阶段都不引入私有文档数据库作为主存储。
3. **AI 默认关闭、默认不上传。** 审阅是产品约束，不是高级设置。
4. **不为路线图造功能。** 没写进验收门槛的能力，不在官网/README 声称已支持。
5. **每阶段都有明确的非目标。** 避免“顺手加一个”导致范围失控。

## Phase 1：编辑可靠性与文件安全（4–6 周）

### 目标

把“能编辑”变成“敢用来写真实文稿”。重点不是新功能，而是保真、恢复、输入法与性能。

### 范围

- **字节保真**：CRLF/BOM/无结尾换行/frontmatter/表格/HTML 块的 round-trip；明确规范化策略。
- **撤销与打开**：打开新文件重置 history；外部内容同步不污染撤销栈；格式命令单事务。
- **冲突与恢复**：外部文件变更检测、冲突提示、自动保存、崩溃恢复、备份策略。
- **输入法**：Windows 微软拼音/搜狗、Linux Fcitx5/IBus、X11/Wayland 矩阵；组合输入期间冻结装饰。
- **工作区**：打开文件夹、递归列出 Markdown、侧栏切换与刷新；相对路径 + 主进程目录边界；脏文稿切换确认。
- **预览治理**：GFM 表格 block widget、本地图片 widget、点击回源码；主进程图片目录边界；外链只允许 http/https；隐藏标记不破坏光标、选区、屏幕阅读器。
- **桌面导出**：A4 PDF 与含本地图片的 HTML；中文、表格、代码块、相对路径本地图片；目录边界与大小预算；原子写目标文件。
- **搜索/替换**：CodeMirror 单文件查找/替换、中文面板、大小写/正则/整词、全部替换。
- **工作区搜索**：`Ctrl/Cmd+Shift+F` 跨文稿只读查找；独立工具进程、8 秒超时、结果点击跳到行列；跨文稿替换不在本期。
- **性能**：10 万字符输入延迟、1 MiB/5 MiB 打开、预览开关、内存基线。
- **可访问性**：键盘操作、焦点、缩放、对比度。
- **测试基础设施**：jsdom/happy-dom 装饰测试、fixture corpus、CLI 临时目录测试。
- **打包 spike**：Windows/Linux 未签名目录包，验证 Electron 运行库与安装路径，不发布。

### 验收门槛

- [ ] 字节保真 corpus 全部通过，或有明确、用户可见的规范化说明（LF/CRLF/BOM/无结尾换行已通过；混合行尾有明确提示；frontmatter/表格/HTML corpus 未建）。
- [x] 打开新文件后撤销不会回到上一个文稿（Windows 真实窗口已验证）。
- [x] 模拟杀进程后能恢复到最后一次快照；原文件不被破坏（Windows 实测；断电/磁盘满未跑）。
- [x] 外部修改同一文件时保存被拒绝，并实时提示；提供载入磁盘/另存为（Windows 实测）。
- [ ] Windows 与 Linux IME 矩阵签字；无丢字/重复上屏/候选框错位。
- [ ] 5 MiB 文档可打开、滚动、搜索；输入延迟有基线且无明显卡顿。
- [ ] 8 小时真实写作 dogfood，无 P0/P1 数据问题。
- [x] 原子写入故障注入（ENOSPC/EIO/EACCES/sync/rename）清理临时文件，旧快照不被覆盖；20 MiB 边界有测试。
- [x] Windows 未签名 staging 目录包可启动、打开/编辑/保存；`resources/app`、preload、renderer、userData 正常（安装器/签名/图标未完成）。
- [x] 表格/图片预览与安全外链已在真实窗口验证：表格点击回源码、离开恢复；图片 data URI 加载并点击回源码；Ctrl/Cmd+点击链接进入系统浏览器，危险协议被主进程拒绝。
- [x] 工作区已在真实窗口验收：3 个文稿侧栏、嵌套路径、脏状态确认、保存；快捷键 `Ctrl+Shift+O` 正确打开文件夹。工作区路径边界与跳过目录有单元测试。
- [x] 单文件查找/替换已在真实窗口验收：中文面板、7 处匹配、全部替换、Ctrl+Z 恢复、Escape 关闭；搜索批次 CI [44985468467](https://github.com/hhxpoint/gather/actions/runs/44985468467) 双平台通过。正则/大小写/整词组合矩阵未逐项跑。

### 非目标

- Tauri 切换。

## Phase 2：AI 审阅与 Tauri bake-off（6–10 周）

### 目标

交付“可控的 AI 修改”：本地优先、用户自带 Key、逐块 diff 审阅；同时用实验回答 Tauri 2 是否能替代 Electron。

### AI 范围

- Provider 抽象：本地 Ollama 优先；云端 BYOK；不内置付费 API。
- 默认关闭、默认不联网；首次开启有明确的数据流说明。
- Key 存操作系统凭据库；不写日志、不进仓库。
- 上下文选择：用户显式选择范围；默认不发全文；不后台索引其他文稿。
- 修改建议：原文范围 + 替换文本；逐块 diff；接受/拒绝；接受后可整体撤销。
- 失败处理：模型超时、断网、返回非法格式时不改文档。
- 审计：本地可选记录“何时使用了哪个 provider”，不记录文稿内容。
- 测试：mock provider、离线、超时、恶意输出、超长输出、并发保存。

### Tauri 2 bake-off

按 [ADR 0001](adr/0001-desktop-shell.md) 执行四项硬门槛：

1. Linux WebKitGTK 兼容性；
2. 中文 IME；
3. PDF 导出；
4. CLI 共享核心。

时间盒 2–3 周，输出 Pass/Fail 证据与“切换/不切换”决策。未通过则继续 Electron，不在官网宣称迁移。

### 验收门槛

- [ ] 默认安装后没有任何文稿数据离开设备；网络请求可在系统层验证。
- [ ] 开启 AI 需要显式操作；关闭后无后台请求。
- [ ] 逐块接受/拒绝可用；拒绝后文档字节不变；接受后可撤销。
- [ ] 模型失败不产生半写文件、不自动重试改稿。
- [ ] Key 不出现在日志、崩溃报告、仓库、UI 截图中。
- [ ] Tauri 四项硬门槛有书面结论；未通过时 Electron 主线不受影响。
- [ ] beta 候选版本通过 Phase 1 的全部数据安全门槛。

### 非目标

- RAG/知识库/跨文稿检索（Phase 3 以后再评估）。
- 自动批量改稿、后台索引、云端同步。
- 插件市场。

## Beta 准备（2–4 个月）

Phase 2 结束后不直接开放下载。先用 2–4 个月把“能给别人用”的条件补齐：

- Windows 代码签名证书、签名流水线、Linux GPG 校验和。
- 安装/卸载/升级/回滚演练；自动更新先做灰度或手动检查，不默认后台更新。
- 隐私说明、第三方 notices、安全报告通道、Issue 模板、故障排查文档。
- 商标、域名、npm 包名、GitHub 组织名检索；若冲突，在 beta 前改名。
- beta 招募与反馈方式：优先 GitHub Issues/Discussions，不默认收集遥测。
- 用 Phase 1 的数据安全门槛做一次完整回归，而不是只看新功能。

Beta 准备不新增产品能力。它占用 2–4 个月，是把公开 beta 推到第 6–9 个月的主要原因之一。

## 公开 beta（从第 6–9 个月开始）

### 目标

让真实用户在不丢稿的前提下使用 Gather，收集编辑可靠性、IME、导出与 AI 审阅的反馈。

### Beta 门槛

- [ ] 签名安装包（Windows/Linux），校验和与回滚方案可用。
- [ ] 数据安全门槛：0 丢稿；冲突/恢复/只读目录/磁盘满测试通过。
- [ ] Windows 10/11、Ubuntu 22.04/24.04、Fedora 当前稳定版完成矩阵。
- [ ] 中文 IME 矩阵签字。
- [ ] AI 默认关闭、默认不上传；隐私说明可读。
- [ ] 崩溃/错误上报默认关闭或明确同意，且不含文稿内容。
- [ ] 许可证、商标/域名/包名清障完成；至少完成检索，改名风险有结论。
- [ ] 支持渠道与 Issue 模板可用；安全报告通道可用。

### 时间说明

一人全职：6–9 个月是合理量级。两到四人：3–6 个月，但需要并行 QA 与 Linux/IME 测试；如果只有开发者没有测试支持，压缩空间有限。兼职投入按 1.5–2.5 倍估算。

## Phase 3：beta 加固与生态（3–5 个月）

### 目标

把 beta 的“可用”变成“可分发、可扩展、可维护”。

### 范围

- **导出**：PDF（CJK 字体嵌入、分页、表格/代码/图片）、DOCX（结构映射，不追求像素级还原）。
- **插件 SDK**：独立包、MIT、稳定 API、权限模型；主题 API。
- **分发**：Windows 签名安装包、Linux AppImage/deb、自动更新、回滚、校验和。
- **CLI  parity**：与桌面端一致的导出/新建/体检；可脚本化；退出码与 JSON 输出稳定。
- **性能/稳定性**：长文档、低内存、启动时间、崩溃恢复。
- **本地化**：zh-CN/en 基础；文案与日期/数字格式。
- **文档**：用户手册、故障排查、隐私说明、插件开发指南。

### 验收门槛

- [ ] Windows 安装/卸载/升级/回滚在干净虚拟机通过。
- [ ] Linux AppImage/deb 在目标发行版通过；Wayland/X11 均可用。
- [ ] PDF 导出无缺字/截断；与基线视觉对比通过。
- [ ] 插件 API 有版本策略、权限说明、示例与测试；MIT 许可证独立。
- [ ] 自动更新有签名校验与回滚；失败不破坏现有安装。
- [ ] 30 天 beta 无 P0 数据事故；P1 有明确修复计划。
- [ ] 文档与 CLI `--help` 一致；没有不存在的命令。

### 非目标

- 多人实时协作。
- 移动端。
- 云端同步/账号体系。
- 企业 SSO/审计后台。

## Phase 4：1.0（3–6 个月）

### 目标

稳定、可维护、可长期使用的本地 Markdown 写作工作台。

### 范围

- 数据格式与插件 API 稳定；迁移与弃用策略。
- 性能与可访问性达标；长期未解决 P1 清零。
- 安全更新流程、依赖升级节奏、Electron/Tauri 决策复核。
- 文档、教程、故障排查、隐私政策、许可证合规。
- 可选的团队/企业需求评估，但不默认做云服务。

### 1.0 门槛

- [ ] 连续 30 天无 P0 数据丢失/损坏事故。
- [ ] 关键平台矩阵与 IME 矩阵再次通过。
- [ ] 安装/升级/回滚/卸载在 Windows/Linux 通过。
- [ ] 插件 API 至少一个 minor 周期的兼容性验证。
- [ ] 许可证、商标、隐私说明、第三方 notices 完整。
- [ ] 支持响应与安全报告流程可用。

## 一人与团队的差异

| 维度 | 一人全职 | 2–4 人团队 |
| --- | --- | --- |
| Phase 0 | 2 周（骨架已存在） | 1–2 周，但并行收益有限 |
| Phase 1 | 4–6 周 | 3–5 周；QA/IME 可并行 |
| Phase 2 | 6–10 周 | 4–7 周；AI/壳实验可分线 |
| 公开 beta | 6–9 个月 | 3–6 个月 |
| 1.0 | 12–18 个月 | 8–12 个月 |
| 主要瓶颈 | 上下文切换、Linux/IME 测试、签名与运营 | 协作成本、接口对齐、评审等待 |
| 风险 |  burnout、测试覆盖不足 | 范围膨胀、多人改同一层 |

团队并不会自动更快：如果 `core`/`editor`/`desktop` 的边界没有守住，多人并行会变成互相阻塞。Phase 0 的文档与 ADR 就是为了减少这种成本。

## 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Markdown 保真缺陷 | 用户文稿被改写，信任崩塌 | fixture + 字节 round-trip；不做静默规范化 |
| CRLF/BOM/编码 | Windows 用户 diff 爆炸 | Phase 1 专项修复；显式策略 |
| 中文 IME 回归 | 无法写作 | 真机矩阵；组合输入冻结装饰；CI 无法替代手工 |
| Linux WebKitGTK 差异 | Tauri 迁移失败 | 四项硬门槛；失败继续 Electron |
| PDF 字体/分页 | 导出不可用 | 固定 fixture；字体嵌入；基线对比 |
| AI 数据泄露 | 隐私事故 | 默认关闭；本地优先；BYOK；日志脱敏 |
| 自动改稿 | 作者失去控制 | diff 审阅硬约束；不提供自动应用 |
| Electron CVE | 安全风险 | 跟踪安全版本；季度升级；签名发布 |
| 签名成本/流程 | 无法分发 | 预算；云签名/HSM；CI 签名 spike |
| 商标/包名冲突 | 被迫改名 | beta 前检索；域名/包名/组织名同步 |
| 范围膨胀 | 延期 | 每阶段非目标；未过门槛不发布 |
| 单人 burnout | 项目停滞 | 缩小阶段范围；公开进度；不承诺日期 |

## 完成定义（所有阶段通用）

一个阶段算完成，必须同时满足：

- 代码、测试、文档三件套齐全；
- 验收门槛有可复现证据，不是口头结论；
- CI 在目标平台通过；CI 未覆盖的 GUI、IME、打印与安装环节，必须记录本地命令、系统与输入法版本；
- 没有未解决 P0 数据问题；
- 没有伪造的测试、截图、兼容性、AI 能力或发布状态；
- 隐私与许可证检查通过；
- 下一阶段的范围与非目标写清楚。
