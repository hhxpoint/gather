# ADR 0009：工作区搜索在独立工具进程中扫描

- 状态：Accepted
- 日期：2026-11-23
- 范围：`apps/desktop`、`packages/editor`

## 背景

单文件查找已经使用 CodeMirror 搜索状态。用户下一个需求是跨文稿查找：输入一个关键词，看到工作区里的命中，点击结果打开文稿并跳到对应行。这个路径不能把 2000 个文件或用户正则放到主进程同步扫描，否则一个灾难性回溯就能让窗口失去响应；也不能让渲染进程直接读盘，破坏现有的目录边界与 sandbox。

## 决策

1. **独立工具进程扫描。** 主进程通过 `utilityProcess.fork` 启动 `workspace-search-worker.js`；渲染层只发送查询与开关，不发送绝对路径。新查询、关闭工作区、窗口关闭和退出都会终止旧进程。
2. **查询编译一次。** 字面量先转义，和正则共用 `RegExp`；默认 `i`，始终带 `u` 与 `g`。逐行执行；零长度匹配主动推进 `lastIndex`，避免死循环。
3. **硬性预算。** 关键词不超过 200 字符；结果不超过 200 条；单文件不超过 2 MiB；一次扫描不超过 64 MiB；每行最多 3 条，超过标记 `truncated`。前 8 KiB 含 NUL 的文件按二进制跳过。
4. **路径重新校验。** 文件列表来自 `listWorkspace`，但读取前仍对每个相对路径调用 `resolveWorkspaceFile`，重新 `realpath` 并确认位于工作区；符号链接逃逸和列表后的文件替换都会被拒绝。
5. **8 秒硬超时。** 主进程持有计时器；超时后 `child.kill()` 并返回“搜索超过 8 秒”的结果。工具进程因 V8 或正则错误退出时，`error`/`exit` 监听器必须消化事件并返回错误，不能让未监听的 `error` 冒泡到主进程。
6. **点击跳转不信任渲染层路径。** 结果只带 `relativePath`、行、列；点击时从当前工作区文件表找回文件，仍走 `workspace:openFile` IPC 与恢复快照清理；编辑器新增 `revealLine(line, column)`，用 CodeMirror transaction 设置选区并滚动到中心。
7. **UI 延迟 280ms 防抖。** 搜索面板位于工作区侧栏，支持区分大小写与正则；结果按命中列出文件、行号、列号与带高亮的单行预览；关闭面板恢复文稿列表。
8. **首版只读。** 不提供跨文稿替换、搜索历史、固定排除规则或结果流式增长；不使用 `ripgrep` 等外部二进制，避免安装包与平台差异。

## 被否方案

- **主进程直接扫描。** 正则回溯或 4 GiB 级读取会阻塞窗口；只靠预算无法约束单条正则的 CPU 时间。
- **渲染进程用 Node `fs` 扫描。** 需要关闭 sandbox 或扩大 preload 权限，破坏现有安全边界。
- **依赖 `ripgrep`。** 需要随包分发额外二进制并处理平台、签名和版本；首版不值得。
- **把文件内容缓存到渲染层。** 引入缓存失效、外部修改和多窗口一致性问题，Markdown 源文件不再是唯一真相。
- **在 worker 里流式追加结果。** 首版结果上限 200 条，单次消息足够；流式会增加取消、排序与 React 状态复杂度。

## 后果与边界

- 每次搜索启动一个短生命周期工具进程，首次响应有进程启动成本；真实窗口在 1184 宽下 8 处结果约 1 秒内可见。
- 正则由用户输入，仍可能触发 CPU 极高的模式；由 8 秒超时和进程终止兜底，应用本身保持运行。已验证 60k 字符 `a` + `^(a+)+$` 在 8 秒被停止。
- 工作区搜索不提供替换、历史、包含/排除 glob、结果分组折叠或流式进度；超过 2 MiB 的文件和二进制文件跳过并在摘要中计数。
- `utilityProcess` 在 Windows 未签名 staging 与 electron-vite 构建中已验证；asar 安装包、Linux 与 dev server 下的 worker 路径仍需后续矩阵。
- 搜索是只读快照；扫描期间外部修改的文件按读取时内容返回，不阻塞保存，也不会覆盖文件。
