# ADR 0007：文件夹工作区是导航层，不是新的文档库

- 状态：Accepted
- 日期：2026-11-22
- 范围：`apps/desktop`

## 背景

项目站一直写着“文件夹就是工作区”，但应用此前只能通过文件对话框打开单篇 Markdown。用户需要一个能看到同目录文稿、快速切换、又保持现有保存/恢复/外部变更边界的工作区。

## 决策

1. **工作区只做导航，不拥有文稿。** Markdown 文件仍然是唯一真相；侧栏文件列表是主进程对当前文件夹的一次扫描结果，不缓存正文、不建立数据库。
2. **打开文件夹由系统目录对话框发起。** 主进程 `workspace:open` 保存 `realpath` 后的根目录，返回 `{ root, name, files, truncated }`。
3. **递归但有边界。** 最多 2000 个文稿、深度 8；跳过以 `.` 开头的条目、`node_modules`、`out`、`dist`、`release`、`coverage` 与符号链接。只列 `.md/.markdown/.mdown/.mkd/.txt`。超出时返回 `truncated: true`，UI 明确提示。
4. **打开文件重新校验路径。** 渲染层只能发送工作区相对路径；主进程再次 `resolve` + `realpath` + 目录包含 + 普通文件检查。绝对路径、`..` 穿越、符号链接逃逸、NUL、缺失路径都拒绝。这样即使渲染层被注入也不能借工作区读取任意文件。
5. **不改变文件安全模型。** 打开工作区文件仍走 `readMarkdownFile`、`watchActiveFile`、自动恢复快照、保存冲突与原子写入；侧栏不提供绕过这些路径的写操作。
6. **脏文稿切换前确认。** `App` 在切换到另一篇前检查 `dirtyRef`；取消则保留当前编辑。打开同一文件不重置撤销栈。
7. **侧栏可关、可刷新、不自动重建。** 外部新增文件不自动推送，用户点刷新；跨重启不恢复最近文件夹。首版不做树形折叠、重命名/删除/新建或跨文稿搜索。
8. **快捷键修正。** `Ctrl/Cmd+Shift+O` 在渲染层曾先被 `Ctrl/Cmd+O` 的 keydown 分支截获，导致误开文件对话框；现在按 `shiftKey` 分流到 `openFolder`。

## 被否方案

- **把文件夹内容写入 SQLite。** 会引入第二份索引与迁移成本，且当前只需要导航。
- **让渲染层直接 `readdir`。** 渲染层没有 Node 能力，也不应该拥有目录读取权限。
- **把绝对路径作为打开参数。** 相对路径 + 主进程根目录校验更小、更可审计。
- **递归跟随符号链接。** 会把工作区边界扩展到用户未选择的目录；首版跳过。
- **自动刷新 watcher。** 会增加复杂度；先提供显式刷新。

## 后果与边界

- 已验证：真实窗口打开 `gather-workspace-qa`，侧栏列出 3 个文稿（嵌套路径可见），隐藏目录/依赖目录/非 Markdown 未出现；打开 `nested/笔记.md` 正常，表格预览可见；未保存切换弹确认；保存后状态更新。
- 未覆盖：最近工作区持久化、树形折叠、文件新建/重命名/删除、工作区内搜索、外部新增自动刷新、Linux/IME 行为。
- 工作区根目录存储在内存，关闭应用即丢失；已打开文稿仍可独立保存。
- 工作区侧栏展示绝对根路径，仅在本机窗口；不会上传或写入公开日志。

## 复现

```bash
npm run stage -w @gather/desktop
# 打开含 Markdown/隐藏目录/node_modules 的文件夹
# 检查侧栏、嵌套路径、脏文稿确认与保存
ELECTRON_RUN_AS_NODE=1 ./node_modules/electron/dist/electron.exe \
  ./node_modules/vitest/vitest.mjs run apps/desktop/test/workspace.test.ts
```
