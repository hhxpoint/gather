Local-first Markdown workspace

Phase 1 · 文件可靠性

把散落的想法，
收拢成一篇。

A quieter place to write.

Gather 是一个本地优先的 Markdown 写作工作台。文件留在磁盘；保存前拒绝覆盖外部修改，未保存内容有崩溃恢复快照。AI 审阅是下一步，不在这一阶段冒充已上线。

02 Principles

工具退后一步，
作者向前一步。

Gather 不想成为另一个需要被管理的系统。它把写作留在文件里，把修改交还给你，把选择权放回工具之外。

The quiet contract

“文件留在磁盘，修改停在审阅线前。”

写作的最终决定权，始终属于写作者。Gather 只负责把材料摆好、把改动说清，然后后退。

File Diff You
  1. 01

    文件优先

    Files first

    工作区就是你选择的一个文件夹。文稿以普通 Markdown 存在，不依赖 Gather 才能打开；备份、同步与 Git，也继续用你原本的方式。

  2. 02

    可审阅的 AI

    Reviewable diffs

    模型先提交候选改动，Gather 再以 diff 呈现增删。你可以逐处接受、拒绝或整次放弃；没有静默覆盖。完整的审阅流程计划在 Phase 2 落地。

  3. 03

    本地 + BYOK

    Local & your key

    选择本地 Ollama，或接入自己的模型 Key。Gather 不内置付费 API，不默认把文稿交给云端，也不绑定某个模型供应商。

  4. 04

    CLI 一等公民

    CLI, first-class

    同一套文件，同一条审阅边界。终端既能检查环境，也能导出内容；计划在 Phase 2 提供的 gather ask 会进入同一个入口。

03 Capabilities

每项能力，
都留一道确认线。

从磁盘上的文件到终端里的命令，Gather 的工作方式只有一条主线：你始终知道发生了什么，也始终能撤回。

01 / Workspace Open format

文件夹，
就是工作区。

打开一个文件夹，侧栏列出全部 Markdown 文稿并高亮当前篇；切换前确认未保存内容。Markdown 原文始终留在磁盘上，Git 也能照常工作。

Plain text / portable by default
02 / AI editing Phase 2 · 计划

AI 写提案，
你写定稿。

AI 的每项修改先以 diff 出现。逐段接受，整次退回，或继续追问。写入只发生在你明确确认之后。

每一次保存，
先过一道确认线。

保存前比较内容指纹，外部修改时拒绝覆盖；写入走临时文件、fsync 与原子替换；未保存内容有恢复快照。Markdown 仍是可移植的纯文本。

写下的内容，

04 CLI

命令行里，
也有同一张书桌。

Gather 的 CLI 是一等入口，不是桌面端的配件。它读写同一批文件，也遵守同一条审阅边界。

First-class terminal

从环境检查到内容导出，再到计划中的 AI 修改，所有路径都从同一个本地工作区出发。

Phase 1 · 源码可用
查看 CLI 源码
  1. 01 Phase 1 · 已可用
    $ gather doctor

    检查 Node、平台、当前工作目录与 AI 配置边界。先弄清环境，再开始写作。

  2. 02 Phase 1 · 已可用
    $ gather export draft.md --format html -o draft.html

    把 Markdown 导出为独立 HTML。桌面端已支持 PDF 与含本地图片的 HTML；CLI 目前仍只支持 HTML，DOCX 尚未实现。

  3. 03 Phase 2 · 计划中
    $ gather ask "收紧第二段，但保留语气"

    把写作请求交给 Ollama 或自有 Key 的模型。提案进入 diff 审阅，不直接覆盖文件。此命令尚未实现，计划于 Phase 2 提供。

    Proposal → Diff → Your call

Note Phase 1 的 CLI 已能从源码运行，但尚无公开发行版、二进制或 npm 包。doctor、new 与 export 已在 Windows 实测并通过双平台 CI；ask 属于 Phase 2 计划。

06 Roadmap

方向写下来，
日期不虚构。

以下顺序是当前意图，不是发布日期承诺。完成状态以代码与发布页为准，而不是这张路线图。

  1. Done

    Phase 0 / Foundation

    打地基

    窗口、编辑器内核、CLI、共享核心、测试与 CI 已经从干净环境跑通，项目站也已部署。

    • Electron 桌面壳与 CodeMirror 6
    • CLI：doctor / new / export
    • Windows + Ubuntu CI
    • GitHub Pages 项目站
    完成 / Complete
  2. Now

    Phase 1 / Reliability

    把文件安全做实

    不做“永不丢字”的口号，而是把字节保真、冲突拒绝、恢复快照、查找替换、表格/图片预览、失败注入与可带走的导出逐项做成测试和证据。

    • CRLF / BOM / 原子写入
    • 外部修改拒绝与恢复快照
    • 强杀恢复、真实 watcher
    • 文件夹工作区 / 侧栏切换
    • 单文件查找 / 替换 / 正则
    • 跨文稿搜索 / 点击跳转
    • 专注模式 / 阅读模式 / 夜读
    • 阅读目录 / 查找 / 代码高亮
    • 窗口 / 工作区 / 文稿恢复
    • 表格 / 本地图片 / 安全外链
    • A4 PDF / 含本地图片的 HTML
    • 未签名预览安装包 / SHA-256
    进行中 / In progress
  3. Next

    Phase 2 / AI & Release

    让 AI 审阅闭环

    只有文件安全与发布门槛稳定之后，才接入模型、签名安装器与更广的 beta。Tauri 仍会在真实约束下评估。

    • Ollama + BYOK
    • gather ask 与逐块 diff
    • 签名安装包 / 自动更新
    • IME 与 Linux 桌面矩阵
    计划中 / Planned

Note 路线图描述产品意图，不构成日期或功能承诺。当前默认仍是 Electron；Tauri 没有通过四项硬门槛前不会替换。
