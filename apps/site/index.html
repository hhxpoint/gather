01 Principles

工具退后一步，
作者向前一步。

Gather 不想成为另一个需要被管理的系统。它把写作留在文件里，把修改交还给你，把选择权放回工具之外。

The quiet contract

“文件留在磁盘，修改停在审阅线前。”

写作的最终决定权，始终属于写作者。Gather 只负责把材料摆好、把改动说清，然后后退。

File Diff You
  1. 01

    文件优先

    Files first

    工作区就是你选择的一个文件夹。文稿以普通 Markdown 存在，不依赖 Gather 才能打开；备份、同步与 Git，也继续用你原本的方式。

  2. 02

    可审阅的 AI

    Reviewable diffs

    模型先提交候选改动，Gather 再以 diff 呈现增删。你可以逐处接受、拒绝或整次放弃；没有静默覆盖。完整的审阅流程计划在 Phase 1 落地。

  3. 03

    本地 + BYOK

    Local & your key

    选择本地 Ollama，或接入自己的模型 Key。Gather 不内置付费 API，不默认把文稿交给云端，也不绑定某个模型供应商。

  4. 04

    CLI 一等公民

    CLI, first-class

    同一套文件，同一条审阅边界。终端既能检查环境，也能导出内容；计划在 Phase 1 提供的 gather ask 会进入同一个入口。

02 Capabilities

每项能力，
都留一道确认线。

从磁盘上的文件到终端里的命令，Gather 的工作方式只有一条主线：你始终知道发生了什么，也始终能撤回。

01 / Workspace Open format

文件夹，
就是工作区。

打开一个文件夹，就打开全部文稿。Markdown 原文始终留在磁盘上，任何编辑器都能继续写，Git 也能照常工作。

Plain text / portable by default
02 / AI editing Phase 1 · 计划

AI 写提案，
你写定稿。

AI 的每项修改先以 diff 出现。逐段接受，整次退回，或继续追问。写入只发生在你明确确认之后。

draft.md proposal 01
12 写作把散落的念头
13 变成另一种噪音。
13 收拢成清楚的句子。
等待你的审阅

03 CLI

命令行里，
也有同一张书桌。

Gather 的 CLI 是一等入口，不是桌面端的配件。它读写同一批文件，也遵守同一条审阅边界。

First-class terminal

从环境检查到内容导出，再到计划中的 AI 修改，所有路径都从同一个本地工作区出发。

Phase 0 · 源码中
查看 CLI 源码
  1. 01 Phase 0 · CLI scaffold
    $ gather doctor

    检查 Node、平台、当前工作目录与 AI 配置边界。先弄清环境，再开始写作。

  2. 02 Phase 0 · CLI scaffold
    $ gather export draft.md --format html -o draft.html

    把 Markdown 导出为独立 HTML。Phase 0 只支持 HTML；PDF、DOCX 等格式留到后续阶段评估。

  3. 03 Phase 1 · 计划中
    $ gather ask "收紧第二段，但保留语气"

    把写作请求交给 Ollama 或自有 Key 的模型。提案进入 diff 审阅，不直接覆盖文件。此命令尚未实现，计划于 Phase 1 提供。

    Proposal → Diff → Your call

Note Phase 0 的 CLI 代码已在仓库中打底，但尚无公开发行版、二进制或 npm 包。doctor 与 export 位于源码脚手架中；ask 属于 Phase 1 计划。
